# SkillBridge AI — Hybrid AI Semantic Matching Architecture

## 1. Executive Summary

SkillBridge AI employs a **transparent, multi-factor hybrid matching engine** designed to score the compatibility between candidates (student resumes) and micro-internship opportunities. 

Unlike black-box AI platforms that output opaque percentages or simulated scores, SkillBridge AI:
1. Evaluates candidates across **4 distinct, weighted dimensions**.
2. Explains the exact mathematical breakdown of every score to both recruiters and applicants.
3. Features an automated **graceful degradation mode** that maintains deterministic candidate matching if embedding models or external LLM services are temporarily unavailable or operating under constrained memory limits.
4. Stores normalized 384-dimensional embeddings behind an isolated `EmbeddingRepository` abstraction ready for seamless transition to PostgreSQL `pgvector`.

---

## 2. Multi-Factor Hybrid Scoring Formula

When both the internship task and the candidate resume have pre-computed vector embeddings, the engine applies the **Standard Hybrid Scoring Formula**:

$$\text{Final Score} = (\text{Semantic} \times 0.55) + (\text{Skill Overlap} \times 0.25) + (\text{Keyword Overlap} \times 0.10) + (\text{Experience Relevance} \times 0.10)$$

| Factor | Weight | Purpose | Calculation Method |
| :--- | :---: | :--- | :--- |
| **Semantic Similarity** | **55%** | Conceptual alignment between internship scope and candidate background | Cosine similarity between 384-dim dense vectors generated by `Xenova/all-MiniLM-L6-v2` |
| **Direct Skill Overlap** | **25%** | Hard technical requirements match | Intersection of required task skills vs. extracted candidate skills normalized by required count |
| **Keyword Relevance** | **10%** | Domain-specific term and terminology density | Tokenized set intersection over non-trivial words ($>3$ characters) |
| **Experience Depth** | **10%** | Practical baseline and project trajectory | Quantized scoring based on verified portfolio items, internships, and project entries |

## 3. Graceful Degraded Fallback Mode

In production environments subject to RAM limits (such as container restarts or initial cold starts without GPU acceleration), the engine automatically detects missing or pending vectors and shifts to **Degraded Deterministic Mode**:

$$\text{Degraded Score} = (\text{Skill Overlap} \times 0.60) + (\text{Keyword Overlap} \times 0.25) + (\text{Experience Relevance} \times 0.15)$$

- **Zero Downtime**: Users can always search, match, and apply even if ML pipelines are initializing.
- **Auditable Flag**: The `isDegraded: true` boolean is propagated directly to the frontend, notifying the user that score weights have shifted to deterministic keyword and skill matching.

## 4. Deterministic Skill Extraction Engine

Candidate resumes undergo deterministic extraction via a curated taxonomy of 80+ engineering, data science, design, and product competencies.

### Regex Boundary Safety
Traditional word boundary regex `\b` fails on technical terms containing special symbols (e.g. `C++`, `C#`, `.NET`, `Node.js`). Similarly, simple character class exclusions misclassify skills followed by punctuation (e.g., `PostgreSQL.` at sentence endings).

SkillBridge AI implements negative lookbehind and lookahead expressions:
```javascript
const escaped = skill.replace(/[.*+?^${}()|[\]\\]/g, '\\$&');
const pattern = new RegExp(`(?<![a-z0-9])${escaped}(?![a-z0-9])`, 'i');
```
This guarantees accurate extraction of `C++`, `C#`, `Node.js`, and `Next.js` without false positives on words like `classical` or `reaction`.

## 5. Embeddings Service Architecture

- **Model**: `Xenova/all-MiniLM-L6-v2` running natively in Node.js via ONNX runtime (`@xenova/transformers`).
- **Singleton Lifecycle**: Prevents redundant model re-initializations across requests.
- **LRU In-Memory Cache**: Up to 500 recently embedded strings are cached in memory, eliminating redundant tensor operations for frequently queried task descriptions.
- **Timeout Protection**: All embedding calls are wrapped in a 15,000ms `Promise.race` timeout guard to protect Node.js event loop health.

---

## 6. PostgreSQL pgvector Transition Roadmap

Currently, 384-dimensional vector arrays are stored in a dedicated PostgreSQL `JSONB` column and queried via `EmbeddingRepository`.

### Future Schema Migration (pgvector)
To scale to millions of micro-internships with millisecond ANN (Approximate Nearest Neighbor) retrieval:

1. Enable the extension:
   ```sql
   CREATE EXTENSION IF NOT EXISTS vector;
   ALTER TABLE "Task" ADD COLUMN "embedding_vec" vector(384);
   CREATE INDEX "task_embedding_hnsw_idx" ON "Task" USING hnsw ("embedding_vec" vector_cosine_ops);
   ```

2. Because all vector retrieval in SkillBridge AI is centralized inside `server/src/repositories/embedding.repository.js`, updating to `pgvector` requires modifying only that single repository class without touching controllers, services, or routes.
